# Lifetime protocol v2

Pure shared implementation lives in `src/game-core/`: `types.ts`, `catalog.ts`, `engine.ts`, `index.ts`. Dynamic IDs are strings, money decimal strings. Exports: `Catalog`, `GameState`, `GameAction`, `ActionResult`, `createGame(seed,catalog,lifeId?)`, `applyAction(state,action,catalog)`, `replayActions(state,actions,catalog)`, `previewWorkWeek(state,catalog,days=7)`, `validateCatalog(value)`, `defaultCatalog`, `getAge(state)`, `getJobReward(state,catalog)`, `getGoalProgress(state,catalog)`.

State fields: `protocolVersion:2`, `engineVersion:2`, `catalogVersion:string`, `seed:number`, `randomCounter:number`, `lifeId:string`, `lifeNumber:number`, `status:'active'|'hunger'|'age_limit'`, `elapsedDays:number`, `money:string`, `bank:{balance,remainder,interestEarned,opened,autoSave,autoWithdraw,reserve}`, `hunger:number`, `sanity:number`, `health:number` (0–10000), `jobId:string`, `ownedItemIds:string[]`, `equipped:{residence?,vehicle?,outfit?}`, `qualifications:string[]`, `education:{qualificationId,collegeId,studyDays}|null`, `careerExperience:Record<string,number>`, `jobEarnings:Record<string,string>` (all lives), `lifeJobEarnings:Record<string,string>`, `workDays:number`, `actionCounts:Record<string,number>`, `workEarned:string`, `lifeWorkEarned:string`, `opportunityIncome:string`, `contract:null|{id,jobId,acceptedDay,deadlineDay,completedDays,payoutSum}`, `offer:null|{id,jobId,expiresDay}`, `lastOfferSlot:number`, `selectedAmbitionId:string|null`, `selectedGoalId:string|null`, `badges:string[]`, `legacy:LegacyChapter[]`, `rebirthCount:number`, `completedLifetimes:number`, `accountLevel:number`, `peakWealth:string`.

Actions use `type` + snake_case IDs:
`work`, `eat{item_id}`, `rest`, `checkup`, `study`, `buy_item{item_id}`, `choose_job{job_id}`, `enroll{qualification_id,college_id}`, `equip{item_id}`, `travel{item_id}`, `deposit{amount}`, `withdraw{amount}`, `bank_settings{auto_save:boolean,auto_withdraw:boolean,reserve:string}`, `accept_contract{offer_id}`, `decline_contract{offer_id}`, `abandon_contract`, `select_ambition{ambition_id:string|null}`, `select_goal{goal_id:string|null}`, `rebirth`.

`applyAction` never mutates inputs; returns `{state,accepted:boolean,dayCost:number,reason:string|null}`. Unknown fields/types and malformed amounts fail. Invalid/unaffordable actions do not advance age/randomness/interest. Ordinary single Work can be fatal. Week preview expands up to seven **ordinary work actions**, unlocks at workDays≥200, and stops before starvation/completion; journal stores ordinary actions, so a week is not a rate bypass.

`replayActions` returns `{state,processed,dayCost,stopReason}` and commits a valid prefix, stopping at first rejection. Ended-state actions reject except rebirth and non-economic preference selection. Rebirth preserves cumulative work/legacy/badges/level only, uses same server-issued deterministic stream and catalog until next prepared checkpoint; no client seed/life ID supplied in sync. New life ID is deterministic `${initialLifeId}:${lifeNumber}`.

## Edge and database trust boundary

Edge `game-sync` authenticates bearer JWT via Supabase Auth. JSON body operation is `bootstrap` or `sync`. Bootstrap reads the account's v2 state and pinned catalog through service-only `get_game_v2_context(owner_id,device_id,request_id,payload)`. Sync includes `requestId`, `baseRevision`, `startSequence` (first new action = acknowledged sequence + 1), `catalogVersion`, `actions` (≤512 and≤64KiB). Client never supplies snapshot, reward or seed.

Prepared response: `{state,catalog,revision,sequence,receipt?,conflict?}`. Exact receipt is returned before revision checks. Conflicts provide current state/revision/sequence. Prepare is read-only except first bootstrap creates a trusted seed/session; explicit initialize acknowledgement creates the fresh state and leaves prior-v1 historical records intact. Edge validates the catalog and complete action envelope, replays trusted state, and calls service-only `commit_game_v2(owner_id,device_id,request_id,payload,expected_revision,expected_seq,next_seq,days_used,state,response)`.

Commit locks owner, checks exact owner-wide receipt first, rejects payload reuse, verifies revision/sequence/CAS and active session policy, enforces bounded cumulative server-clock day allowance (4/sec, burst8, accrued max1200 = five minutes), and atomically writes state, incrementally verified job totals, legacy and receipt. Service-only caller is trusted engine; authenticated client has no direct execute permission. Outcome `{state,revision,sequence,processed,stopReason,requestId,serverTime}`; sequence advances only accepted action count. If partial rejection the remaining suffix must be dropped/reviewed, never auto-generated with another ID. Revisions increment per committed accepted prefix. Rate failures return no accepted gameplay and must not discard the journal silently.

Initial implementation uses one writer checkpoint CAS; explicit takeover clears stale journals only after user acknowledgement. Old cloud MVP runs are archived rather than converted into age/qualification claims. Existing earnings stay separate historical records. Catalog publishing is privileged and validates identical shared rules; immutable catalog version+digest, supported schema/engine 2, default activation affects newly started lives: context returns nextCatalog, rebirth binds it, and receipt confirms the new catalog. Mobile caches nextCatalog and pauses further ranked actions at a catalog-changing boundary until verification.

## Deployment and authentication evidence (2026-10-12)

Lifetime/catalog/default-title migrations and both Edge Functions are deployed. `game-sync` retains platform user-JWT verification and independently authenticates with `getUser`. `game-content-publish` has `verify_jwt=false`, accepts configured project secret keys in `apikey` (legacy bearer fallback supported), and validates its own privileged credential against injected project secrets in constant time. It accepts neither ordinary user JWTs nor public publishable keys.

Actual hosted publisher verification confirms public key 401, wrong digest 400, and privileged idempotent publication 200 for the unchanged `lifetime_v2_1` artifact. No activation, catalog prices or existing-life state were changed by this check. The developer CLI sets both `apikey` and `Authorization` from its in-memory trusted credential; never place that credential in the app.
